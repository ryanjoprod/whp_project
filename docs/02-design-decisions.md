# WHP Program - Design Decisions (and why)

Each entry: decision, then the reason. Revisit only with a migration plan.

1. **Dates inline, not a `dates` table.** A separate table adds orphan rows, joins and save-order problems for no gain. Cost: five columns repeated on dated tables.
2. **`date_sort` = JDN of the start date, NULL if unknown.** One sortable integer; ranges sort by start; quality never moves the sort.
3. **Keep both events and facts.** Facts for single-subject conclusions (person_facts, relationship_facts; marriage is a relationship fact). Events for multi-person happenings with roles. One UI list later; no `birth_ref_index`, pick by date.
4. **Events are source-scoped.** Same file-collision reason as persons. Roles must point at persons in the same source.
5. **Documents are source-scoped, agents global.** Documents belong to one source's file and nothing references them; agents (authors, repositories) are shared and remapped on import.
6. **Place ids from files are remapped on import**; `place_description_id` has no FK so unresolved ids can be cleared (original text kept).
7. **One person, one aggregate.** `person_links.person_id` is the PK; linking moves; merging folds a whole group.
8. **Row keys `sourceId:localId`** keep each imported file's local ids intact while the database stays globally unique.
9. **Cascade for owned children, RESTRICT for sources/citations.** Deleting a person cleans up everything they own; you cannot delete a source that is still cited.
10. **Additive-first schema evolution.** `ADD COLUMN`, new tables and indexes are cheap in migration; changing constraints or column types needs a table rebuild, so decide those before real data.
11. **v9 is the baseline.** v8 and lower were pre-release drafts whose layout changed while the schema was being built, so the version number was ambiguous. Opening a project below v9 is refused with a clear message ("create a new project"); no migration from them exists or is needed. Migration machinery starts at v9 -> v10. From now on any schema change bumps `kSchemaVersion` and ships with a migration step.
12. **Attribute-level citations and notes skipped.** Gramps' own SrcAttribute (source/citation) has none either; additive later.
13. **Place and agent ids are `<sourceId>:<fileId>`.** Deterministic, so there are no collisions across files and re-imports update instead of duplicating, with no mapping table. Duplicate real-world places are merged later by hand.
14. **Place cycles are refused in storage, regardless of dates.** Every route (import, future editor, hand-edited files) goes through `save`, and everything that walks the hierarchy can then assume it ends.
15. **One Date editor, built on `DateParts`.** Pure logic lives in `libs/gedcomx/date_parts.h` (`DateKind {Regular, Before, After, About, Range, Span, TextOnly}`, `SimpleDate{year, month, day}` with 0 = not given and negative year = BC, `DateParts{kind, calendar, quality, start, stop, text}`). The UI (`window_date_editor.cpp`) is a single "Date" modal opened from any date field with a `DateEditorTarget`; only the owning editor renders it, and it must be rendered inside the parent popup's scope. OK returns a complete `gedcomx::Date` (original, formal, calendar, quality, sortValue); Cancel changes nothing. Each new dated editor (fact, event, place) adds one target value and two calls. `Window::renderDateInput(id, date, buffer, size, width)` is the shared text box plus `...` button.
16. **Formal date forms.** Regular `+1900-05-05`, About `A+1900`, Before `/+1900`, After `+1900/`, Range and Span `+X/+Y` (told apart on reload by the generated original text starting with `from `). Text-only has an empty formal. `formal` holds the numbers of the date's own calendar, so it is standard GEDCOM X only for Gregorian. A formal date the editor cannot parse reopens as Text only with its words and is only rewritten if the user presses OK.
17. **Only Gregorian and Julian compute `sortValue`.** Other calendars (Hebrew, French Republican, Persian, Islamic, Swedish) are stored but have no sort value until conversion is written. Text typed straight into a date box becomes a Text-only date with no sort value; the Date editor structures it. A free-text parser ("5 May 1900" -> Regular) is a possible later addition.
18. **Place Editor: one collector, and the working copy keeps what the form does not show.** `collectPlace()` builds a `PlaceDescription` from the buffers every frame (title readout, error line, OK enabled state, and what is saved). It starts from `workingPlace_`, so confidence, language and citations survive an edit. Rule for every editor: never build the saved object from the form alone, or fields the form does not show are lost.
19. **Place title is derived (`placeTitle`, `libs/gedcomx/place_logic.h`):** primary names up the FIRST parent chain, loop-safe. The parent picker excludes the place itself and its descendants (`placeDescendants`); the storage cycle guard (decision 14) is the backstop.
20. **Places are managed under Data -> Places...** (filterable list with New and Edit; `PlaceEditorOwner::App` or `List` decides which scope renders the editor). There is no delete yet: `place_description_id` has no FK, so deleting needs a "who uses this place" check first. Places carry citations through the same Citation Editor (`CitationEditorOwner::Place`); modals nest Place Editor -> Citation Editor -> Date editor.
21. **Facts and events are separate tabs.** In the Person editor, Facts = single-person conclusions (`person_facts`), Events = shared multi-person events. A merged list is still the long-term plan (decision 3). A fact stores a place as free text (`original`, what the source says) plus an optional link (`descriptionId`, picked with the shared place picker).
22. **Events are edited from a person and saved immediately.** Event roles have a foreign key to the person, so an event cannot be saved for an unsaved person; the Events tab says "save the person first". Shared records (events, citations) save at OK and not with the person, so cancelling the person editor does not undo them.
23. **Event Editor = the shared event + this person's role.** Opened from the Events tab (New event, Edit, Add existing event). It starts from the loaded event, so other people's roles, confidence and role notes survive. Other participants are read-only; each person joins an event from their own editor. One `EventChange` channel carries save, remove-from-event and delete; App deletes an event whose last role was removed. Loaded events carry row keys, new ones local ids; App converts to local ids only when the id really starts with `<sourceId>:` (`stripRowKeyPrefix` chops blindly). Modals nest Person editor -> Event Editor -> Citation Editor -> Date editor.
24. **Where app files live.** Window state (`window_state.json`) is per user, in `userDataFolder()` (`SDL_GetPrefPath("WHP", "WHP Program")`, under AppData\Roaming on Windows): the window is created at startup, before any project is open, and some sessions have no project. Physics sliders (`physics_settings.json`) are per project, in the project folder next to the `.db` and `.whproj`; they load when a project opens, defaults are used otherwise, and Save Settings with no project open only logs a warning. Depth, max visible nodes and the layout (`settings.layout`, "graph" or "tree"; missing means graph) stay in the `.whproj`. A bare relative path (`"window_state.json"`) resolves against the working directory, which is the build folder: never use one for saved data. Save and load must use the same path helper.
25. **Backups are a manual File -> Back Up Project... copy.** `Database::backupTo` (`VACUUM INTO`, a consistent copy of the open database, refuses to overwrite) plus the `.whproj`, `sources/` and `physics_settings.json`, written to a new `<ProjectName>_backup_<date>_<time>` folder the user picks the parent of. The copy is itself a valid project, so restoring is opening its `.whproj`. The source export already carries persons, relationships, events, places, citations and the other sources it cites; agents and documents are not exported because the app has no way to create them (they exist only if an imported file had them) and the backup keeps them.
26. **Canvas menus and the Details panel.** The three right-click menus (person node, relationship line, empty canvas) live in `Window::renderContextMenus` and share `editMenuItem`, which greys an item out in the Aggregate view with the usual tooltip (plus an optional extra condition). Right-clicking a node also selects it. "Create Relationship..." on a node calls `requestNewRelationshipEditor(&person)`, which pre-fills Person 1 and locks the source exactly as picking them does. "New Person..." on the empty canvas works in every view but needs an open project. The Details panel shows names, gender, facts (a linked place shows its full title via `factSummary`; the typed text is the fallback), attributes, addresses, events, and the couple/parent/child lists. Its events use their own list (`detailsEvents_`), requested once per selection (`pendingDetailsEventsRequest_`) and reloaded by `invalidateDetailsEvents()` wherever events can change (event save, project close, source import). The Aggregate view shows a note instead of events: a merged person's events span several source records.
27. **Tree layout is pure logic in `libs/gedcomx/tree_layout`; the canvas only draws it.** `layoutTree(TreeLayoutInput{people, couples, parentChild, rootId})` returns `TreePoint{x, y}` in person-widths and rows, with no UI, database or SDL, so it is unit tested (`tests/gedcomx/test_tree_layout.cpp`). Partners form one unit (chains such as B-A-C are allowed), so partners always stand side by side. Rows come from the longest parent-to-child path (root row 0, ancestors negative, parentless units pulled down next to their children). Each row is ordered by BFS discovery and then barycenter sweeps, and positioned by pulling units toward their parents/children and removing overlaps with pool-adjacent-violators (`nonDecreasingFit`); `kUnitGap = 0.5`; the root ends at x = 0. `Window::applyTreeLayout` recomputes only when its input changed, scales by `kTreeSpacingX/Y` and writes `nodePositions_`. Dragging nodes is locked in Tree mode (the layout owns positions). View -> Layout switches between Graph and Tree and the choice is saved per project. Tree lines: the couple line joins partners, and children hang from its midpoint (or from a lone parent) down to a shared bar and then to each child; Graph mode keeps the straight arrows. Couple lines stay the right-click target in both modes.

## Main window (Phases 1-3 done)

The main window is borderless (`SDL_WINDOW_BORDERLESS | SDL_WINDOW_RESIZABLE`) and its title bar is an ImGui window ("TitleBar", `window_titlebar.cpp`). An open modal popup blocks input to every other ImGui window, and the OS does not know where the title bar or resize edges are unless told.

- **Phase 1 (done): native frame behavior.** `SDL_SetWindowHitTest` (`Window::hitTestCallback`) tells the OS where the resize edges (6 px) and the draggable title strip are, so Windows handles moving, resizing, double-click maximize and snapping. The strip starts after the Data menu (`menuRightEdge_`, an `std::atomic<int>` because the OS calls the callback). Minimum size 720x420. Minimize, maximize/restore and close are drawn and hit-tested by hand on `ImGui::GetForegroundDrawList()` (`renderWindowButtons`), so they keep working while a modal is open. The title strip is one color: `FramePadding.y` is raised and `WindowBg` set to `MenuBarBg` around the TitleBar window so the menu bar is exactly `kTitleBarHeight` tall.
- **Phase 2 (done): layout follows the window.**
  - *Popups stay on screen.* `Window::beginModal` replaces every `BeginPopupModal`; it calls `fitNextWindow(name)`, which caps the size to the main window (minus `kPopupMargin` and the title bar) and pulls the current position back inside every frame. ImGui centers a popup only the first time it is shown and then keeps its position, so a shrunken window left popups past the edge. The same helper is used by the Log and Settings windows.
  - *Live redraw while the OS resizes.* The OS holds the main loop during a resize drag. `Window::setLiveRedraw` registers an SDL event watcher that calls `App::renderFrame()` on `SDL_EVENT_WINDOW_EXPOSED`, only while `allowLiveRedraw_` is true (inside `processEvents()`), so it never draws mid-frame. `run()` must still call `renderFrame()` itself once per loop; the watcher is only for the drag. Without that call the window draws only on EXPOSED events (slow, then black without the watcher).
  - *Gray window after idle:* not reproduced; parked. If it returns, look for `RenderPresent failed` in the log.
- **Phase 3 (done): remember the window.** `WindowState{valid, rect, maximized}` with `serializeWindowState`, `deserializeWindowState` and `fitRectToDisplays` in `src/app/window_state.h/.cpp` (pure, covered by `tests/app/test_window_state.cpp`). `fitRectToDisplays` picks the monitor holding most of the saved rectangle, enforces the minimum size and the display size, pulls the rectangle inside, and centers it on the primary display when its monitor is gone. The window is created with SDL window properties (position, size, maximized), so there is no flash at a default size. `Window::updateNormalRect()` (called from `processEvents()`) remembers the last NORMAL rectangle, because SDL reports the maximized rectangle while maximized; `captureWindowState()` is called after the main loop and App writes the file.
- **Parked: menus usable while a popup is open.** Not possible with ImGui modals (they block every other window by design). It would mean making the 16 `BeginPopupModal` editors and dialogs non-modal, with a single-editor guard (each editor owns one shared working copy), rebuilt nesting, and confirmation rules for File actions during an edit. Estimated 5-6 steps with real state risk. Only do it if the menus are missed once real data entry has started.

## Out of scope for v1 (parked)

Gallery tab (after the map view); export-all-sources (one file per source; check `person_links` in `gatherSourceExport` first); import that keeps existing values when the file is silent; export of agents and documents (places are exported); automatic safety copy of the project when it opens (last few kept in the project folder); non-Gregorian `date_sort` conversion; deleting places; adding other people to an event from inside the Event Editor (people join from their own editor today).
